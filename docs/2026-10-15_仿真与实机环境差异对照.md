## 1. 两张系统图

**SITL 链（3090 电脑上全软件）**：
```
gazebo 物理仿真器（模拟机体/世界/两个相机画面/深度相机/IMU）
  ├─ 合成双目图像 ─→ VINS（视觉里程计：从图像+IMU 算位置）
  ├─ 合成深度图 ──→ EGO-Planner grid_map（避障规划器：看障碍、算绕行路线）※输入源定义表见 3.1（v3 已闭合）
  ├─ 合成 IMU ────↗（与图像同一仿真时钟）
  ├─ 真值(truth)输出 → 判读用（仿真能知道"真实位置"）
  └─ 机体物理 ←─ PX4 飞控(SITL 版,同版本固件) ←─ mavros(本机进程通信) ←─ px4ctrl/规划器
所有节点读同一个仿真时钟；无遥控器（RC）——见 3.6
```
**实机链（真无人机）**：
```
D435 实感相机（双目灰度+深度，自带硬件时钟，USB 进机载电脑）
PX4 飞控（FMU v6C 真硬件，同版本固件 v1.17.0，自带晶振）
  ├─ IMU 从飞控经串口线(921600 波特率)→mavros（路上有延迟抖动；曾实测提频到 203Hz）
  ├─ 深度流供避障规划（rs depth 640 配置在役）
  ├─ VINS/规划器/控制全跑在 NUC 机载电脑（CPU 弱于台式机，与相机抢 USB）
  ├─ 电池供电（电压随放电下坠，监控三线 14.2/14.0/13.2V）
  ├─ 遥控器 RC 经飞控（CH5 模式/CH6 命令开关——人肉终极保险，仿真没有）
  └─ 无真值——判读只能用 VINS 自己的输出做相对评价（见 3.8）
三个物理时钟各走各的+一条带宽有限串口+一条 WiFi 地面链路
```

## 2. 名词表（自创词与专有名词一律在此解释）

| 术语 | 含义 |
|---|---|
| **VINS** | 双目视觉里程计：从左右相机画面+IMU 推算当前位置的算法。"不用 GPS 也知道自己在哪"的核心。 |
| **特征点** | 图像里容易认出来的小图案（角点、纹理斑点）。VINS 靠连续画面追踪它们推算运动；画面越"素"点越少。 |
| **配对率（stereo 配对率）** | 一帧里左右目成功配上对、可用于定位的特征比例（0~1）。**双目 VINS 的口粮指标**：低于 0.10（本校准阈）会"饿"——可用点太少→定位发散。供给门=起飞前先测它过不过阈。 |
| **供给饥饿** | 点不够吃的状态：VINS 拒帧/乱估，表现为位置突跳或持续慢漂。 |
| **j0d** | 项目自建的位置质量判读指标族：算"单帧跳变"（位置读数瞬间跳多远，物理不可能的真跳=判负）与"慢漂"（位置沿一个方向持续爬）。 |
| **coh（一致性）** | 漂移的方向性度量（0~1）：≈0=误差像随机噪声来回抖（健康）；≈1=位置沿一个方向持续偏（系统性慢漂，病态）。 |
| **彩票族/起飞彩票** | 项目自创词：起飞瞬间随机失败（弹射上天或原地不起），同代码同配置一轮好一轮坏像抽彩票。SITL 侧已定案=H4；实机侧有 V2 六连爆前科（一批六轮连续失控爬升，未定案）。 |
| **H4** | SITL 起飞彩票根因：解锁后 4-8 秒爬升段推力指令从 0.26 冲到 0.98 满推→弹射；正常轮只到 0.71。ulog（飞控黑匣子日志）逐条对比定案。 |
| **J2** | 贴障碍绕行时（<1.1 米）障碍占满画面→特征骤减（配对率 0.91→0.01）→1.5-7 秒后位置跳变。"躲得越漂亮，看得越瞎"。**v3 升格独立差异类，见 §3.9。** |
| **transit 慢淋** | SITL 特有慢漂族（98% 集中在平飞转移段）：位置像淋雨般单向浸湿，coh≈1。源于仿真渲染域，实机健康态没有。 |
| **敌对态** | 项目自创词：VINS 持续异常（狂跳/发散）的轮次。曾疑旧机 83% 敌对是算法病，双机对照定案为机器层问题（同代码 3090 上只剩 17%）——三大翻案之一。 |
| **真值（truth）** | 仿真里 gazebo 直接告诉你的"真实位置"（上帝视角）；实机没有上帝视角，只有 VINS 自己说的位置。见 3.8。 |
| **ulog** | PX4 飞控的飞行日志（黑匣子），两域都有，实机从 SD 卡/mavros ftp 取。 |
| **EKF2 / EV** | EKF2=飞控内部状态融合滤波器；EV=外部视觉定位输入。在册定案 E1：EV 融合全项目从未启用，位置链路实际=VINS→控制桥接，两域同构。 |
| **mavlink / mavros / fcu_url** | mavlink=飞控通信协议；mavros=协议接进 ROS 的桥；fcu_url=mavros 找飞控的地址——SITL 用本机网络地址（udp），实机用串口设备（/dev/pixhawk:921600）。 |
| **td** | VINS 配置里的"时间偏移"参数：补偿图像与 IMU 的时间错位。**两域配置值不同**（见 3.7）。 |
| **timesync** | 实机上的对表机制：软件持续估算"飞控钟 vs 电脑钟"的偏移并修正时间戳（含串口传输延迟剥离）。 |
| **δ（相机时戳差）** | 左右目图像时间戳之差。双目要"同时"拍才能配对。实测两域都≈0（实机硬件同步；SITL corridor 实测 36,519 对全 0）——已拉平。 |
| **HAFIX** | 项目自建安全链：VINS 失明→自动盲降→必要时空中断电的保护梯子。SITL 50 轮验证 87% 成功；实机已部署但"空中断电"一步未实测（见 3.6）。 |
| **failsafe** | 飞控的故障自保逻辑（如失控返航/自动降落）。实机有一组参数需首飞前逐项落值；SITL 未做此对齐。 |
| **no_RC** | 在册定案：SITL 的控制栈根本不订阅遥控器话题（代码级证据）——遥控相关行为在仿真里结构性测不到。 |
| **AprilTag** | 黑白方格基准标签。实飞计划贴障碍物上丰富特征；仿真给箱子贴同款=让"看的东西"同构。 |
| **min_surf / 避障 min_dist** | 两个"离障距离"口径（**禁混用**）：min_surf=真值×逐 world 真表的正源净距；min_dist=RESULT.txt 门值，**判读器帧系+版本双错配已定案，全量禁引**（P0-2 立案件）。 |

## 3. 差异类逐类展开（v3：十类）

### 3.1 感知输入域（图像/深度/IMU）

**两域各是什么**：SITL 图像=gazebo 渲染的合成画面（理想光照、无传感器噪声，特征多少由我们搭的世界决定）；深度/点云=仿真深度传感器模型；IMU=物理引擎按噪声模型合成后注入。实机：双目灰度=D435 真实光电（真实噪声/曝光波动/出厂内参带标定残差）；深度=同相机深度流（rs depth 640 在役）；IMU=飞控芯片实测经串口下传（203Hz）。

**差多少**：
- 纹理/配对率（重头）：旧纯色世界 plain **0.16-0.28**（勉强过阈）；旧障碍世界 obstacles **0.05-0.08**（**饥饿带**——曾一批实验特征饿死全灭，"纹理一维定生死"的实证）；新走廊世界 corridor **p50=0.810**（阈值的 8 倍）。直观换算：corridor 对 plain=供给翻约三倍；obstacles 对 corridor=从饿死到吃撑。实机室内+AprilTag 预期≥corridor 水平。
- 相机参数级：D435 出厂内参 fx≈387.5、基线 50mm、帧率 29.98Hz（实测）；SITL 相机模型的分辨率/基线/内参是仿真配置值——**参数级对照表待核项①**（网络恢复后从两侧配置文件实拉成表）。
- **深度/障碍感知链同构性：待核项②——v3 已闭合**（定义表如下）。
- IMU：实机 203Hz+串口延迟抖动（相邻消息到达时差 p50=0.039ms/p95=1.88ms）；SITL 常配 223Hz 理想注入（频率网格 50/125/223Hz 在册）。噪声谱：实机=真实（含机体振动灌入），SITL=参数化模型。

**规划器障碍输入源定义表（待核②闭合件，2026-10-17 实拉）**：

**对结果的影响**：①仿真绿率强依赖"考题难度"旋钮（纹理），不能直接换算实机绿率——但把纹理做到 AprilTag 同构后特征供给维同构；②IMU 抖动实测无害（VINS 逐条用自带时戳算间隔），但这是实测结论非架构保证，极端负载下是监控面；③深度链已核同构（上表）——**避障行为的代表性恢复**，残余边界=深度噪声模型（仿真无噪声 vs 实机主动 IR）与 min-Z 量程（见受限空间节）。

**对齐状态**：corridor 纹理已拉到 8 倍阈；③C 终局册 AprilTag 同构+近距判据（贴箱 1.2 米内配对率不塌，治 J2）已做（H-dJ2 在册）；待核①③④仍开放（见 §4 排序）。

### 3.2 时间与时钟域

**两域各是什么**：SITL 全节点读同一仿真时钟（/use_sim_time），图像/IMU/控制天然同轴。实机三个物理钟（飞控晶振/相机传感器/机载电脑）+timesync 软件对表（含串口传输延迟剥离）。

**链路区别**：对表之后还有传输层——实机 IMU 走串口（带宽约 50 条消息/秒封顶，加话题要精打细算；延迟抖动见 3.1）；历史上踩过"串口投递随机丢一半"的坑（已定案规避：重要命令重发确认）。SITL 的 mavros=同机进程间通信（微秒级、无带宽概念）。另实机 IMU 时间戳=飞控侧时刻经 timesync 映射修正，SITL=仿真钟直给。

**对结果的影响**：时间对不齐=图像与 IMU 时刻错位→把前一瞬的运动安到后一瞬的画面→漂移或跳变。当前对齐水平（δ 两域 0、抖动无害带）不构成风险，但**任何新增话题/负载都可能吃掉对表余量**——架构上永远要盯的一类。

### 3.3 动力学与执行域

**两域各是什么**：SITL 机体=gazebo 模型：电机理想执行、无振动进 IMU、无气动/地面效应、电池理想。实机=真实 250 级机架：电机响应延迟、桨弹性、机体振动直接灌进 IMU、起飞/近地气动效应、电池电压随放电下坠。

**差多少**：**无对齐数字**——SITL 用 iris 默认参数，没人按真机质量/惯量/电机辨识换过（待核项③：可换但需要真机参数，目前没有）。只能定性：理想执行 vs 真实执行。

**对结果的影响**：①**控制参数（PID/推力斜坡）SITL 调好≠实机适用**——H4 修复在 SITL 验证后，实飞窗仍有真机动力验证面（预授权链在册）；②起飞彩票两域都有（SITL=H4 定案；实机=V2 六连爆前科），**同症异因风险**——不能拿 H4 修复给实机打包票；③振动进 IMU 是实机独有输入。

### 3.4 计算平台与运维域

**两域各是什么**：SITL 全家桶在 3090 台式机（多核富余、磁盘 400G+）；实机全家桶在 NUC（CPU 弱、内存 15GB、与相机抢 USB、磁盘紧张带 88%、电池供电、WiFi 地面链路）。

**差多少（硬数字）**：机器层影响实测——同代码旧机 83% 敌对 vs 3090 同栈 17%（双机对照定案）；内存泄漏两域不同带（实机 1.44-2.3GB/h vs SITL 回放域 0.95）；实机独有：USB 断链前科（已物理固定+自愈脚本）、**整机非正常停机前科**（一次静置实验中 10:22:38 整机断电级停机，原因未定案——供电稳定性是真实风险面）、电池电压监控三线（14.2/14.0/13.2V）、WiFi 断链前科（watchdog 在役）。

**对结果的影响**：任何数值结论**绑定平台**；实机有整套运维纪律（5 小时窗重启制/半小时飞行≈1.1GB 内存安全/磁盘预检门）——仿真没有这些约束，长时程结论不能直接外推。

### 3.5 环境场景域

**纹理/特征**：见 3.1。**慢漂（coh=0.0007 的含义）**：实机静置 coh=0.0007（误差≈纯随机噪声，无方向性累积）；SITL 慢淋 coh≈1.0（位置单向持续爬）。**差三个数量级且性质不同**（随机抖 vs 系统爬）。用户已裁定对齐（③C 终局册：先除源[渲染域病根]，除不掉才参数补偿；丙册 T 线定案=非戳面道，袋域戳治理不可治且有害）。实飞环境（真实房间尺寸/光照/地面）本身与 SITL world 几何不同，AprilTag 是把"关键特征源"对齐的抓手。

### 3.6 控制与安全链域

**两域各是什么**：
- **遥控器（RC）**：实机有遥控器接飞控——CH5 拨杆切手动/自动模式、CH6 切命令流，是"人肉终极保险"；SITL **没有 RC**——在册代码级定案 no_RC（控制栈不订阅遥控话题），遥控相关行为在仿真结构性测不到，CH5/CH6 真实拨杆面=首飞窗现场确认件。
- **failsafe 参数**：实机有一组飞控自保参数需首飞前逐项落值（十五项清单在册）；SITL 未做对应配置对齐——**待核项④**：两域 PX4 参数集一致性未逐项对照。
- **安全链验证深度**：HAFIX 在 SITL 50 轮 87%；实机已部署，但"空中断电"这一步只做过地面 unarmed 预验（命令握手 PASS），空中物理效果未实测=首飞窗保护件。
- **飞控传感器组**：实机 FMU v6C 还带气压计/磁力计等真传感器（磁场环境/标定残留真实存在）；SITL 侧这些是合成理想值。EKF2 在两域都跑，但输入的"真度"不同。

**对结果的影响**：仿真永远验不了"人机接管"这条最粗的保险；failsafe 与 HAFIX 的实机生效面靠首飞窗现场件兜底——这决定了**实飞首日必须带着现场确认清单**（在册：检查单 v1 十九条）。

### 3.7 系统部署与配置域

**两域各是什么**：软件本体刻意同构——同一 git 仓（UAV_NUC）、同一版本、部署时对 md5（两域跑的是同一份代码，这是项目纪律保证的）。**但配置层是两套**：实机用 config v0（实机标定/td/曝光参数），SITL 用 sim 域配方（另一套 td/外参/相机参数值）——两套 yaml/launch 文件并存，值不同（td 时间偏移在两域的合理值本来就不同，因为时间架构不同[3.2]）。起栈脚本也不同（SITL 批跑脚本 vs 实机 reboot stack 脚本）。

**对结果的影响**：代码同构+配置异构=**"同一算法在两套参数下运行"**。比较两域结论时必须同时引用配置快照（③C 终局册的结论绑定制：world md5+固件指纹+参数快照+VINS config 快照，就是为这个）。风险面=改了一域配置忘了另一域（在册有"双副本部署对账"坑史）。

### 3.8 判读与验证方法论域

**两域各是什么**：SITL 有**真值**（gazebo 上帝视角告诉你真实位置）——可以算绝对误差（到位距离/轨迹全误差 ATE/真跳变 vs 伪跳变）；实机**没有真值**——只能用 VINS 自己的输出做相对评价（走 30 米往返差多少米、悬停一分钟漂多快、单帧跳变幅度）。

**差多少**：这是方法论级的鸿沟——实机"往返差 0.058m"能证明误差不大，但不能像仿真那样把误差归因到每一段；实机判读正源（九袋画像）全是相对量，仿真判读正源（j0d/combo 436+505 轮）全是真值对照量。

**同一物理量多口径（v3 新增，P0-2 立案消费）**：即使都在 SITL 侧，"离障距离"也有两套口径——`min_surf`（geom 审计：真值×逐 world 真表，**正源**）与 RESULT.txt `避障 min_dist`（批 harness 门值，2026-10-17 定案=**判读器帧系+world 版本双错配**：箱表为 anchor 移位 odom 帧且冻结 v6 版本，truth 为 gazebo 原帧直比；0.000=轨迹穿越幻影箱区，悬停漂移轮/导航轮均实证）。**全量禁引 min_dist，一切对外净距陈述绑定 min_surf**；详见《P02_判读双口径立案.md》。判读工具族新增一条铁律：**引入任何几何判读量前先核箱表帧系与 world 版本一致性**。

**对结果的影响**：①两域的"质量"数字**不可直接互比**（一个是绝对误差、一个是相对闭合差）；②实机出问题时定位手段受限（没有真值做仲裁，只能靠交叉证据——USB 案当年就是这么破的）；③仿真结论向实机迁移时，验证方法本身要换一套；④同域多口径必须先立案定源再引用（本条即例）。

### 3.9 J2 域（v3 升格：从名词表升为独立差异类）

**两域各是什么**：J2=贴障碍绕行（<1.1m）时障碍占满画面→特征骤减→配对率塌陷（0.91→0.01）→1.5-7s 后位置跳变。SITL 侧是合成纹理世界：纹理是否"成片消失"由我们搭的世界决定；实机侧是真实光电：曝光波动/近距失焦/纹理物理坍缩都会让特征成片消失——**实机的 J2 触发面更宽**。

**SITL 是否复现 J2？——复现，且已量化（在册证据链）**：
- v6 批（③C v1.5）：贴箱轮 J2 塌陷 **3/5** 复现（贴行时配对率塌到饥饿带）；
- C-5 批（v7.0 层）：同轮分箱分离——tag 箱贴窗 p50 **0.55-0.85**（≥0.3 门）vs 对照 Wood **0.17**/Bricks **0.03**=无特征面塌到 v6 量级复现；
- v7.3 真形态批（C3F73）：tag 贴窗 **0.49-0.81** 维持 / Wood **0.03** 塌陷 / **Bricks 0.81 未塌=形态依赖新发现**（H-dJ2 收窄注记：塌陷与否取决于箱面形态的富特征供给，非"贴箱必塌"）。
- **tag 解除耦合（H-dJ2 成立）**：富特征面（tag）在贴箱距离上维持配对——SITL 证明了"J2 可用富特征治"，这正是实飞方案（障碍贴 AprilTag）的依据。

**核心张力（v3 点破）**：**"避障"的成功条件（贴近障碍绕行）与 VINS 的失败条件（贴近就瞎）是同一个物理动作区间。** SITL 用合成 tag 把失败条件"治掉"后测的是**理想供给下的绕障几何能力**；实机在同一区间的实际表现=绕障能力×J2 残余触发率的联合结果。因此 SITL 在最要命的贴障区间**系统性偏乐观**，实机折扣必须声明。

**实机折扣声明（引连）**：①自动曝光暂态/眩光/近距失焦 sim 不建模（受限空间差异节）；②tag 工艺面（下洗掀角/卷边）sim 无（同节）；③贴箱配对率实机预期低于 sim 带 0.49-0.81（首飞建议单 §7 折扣声明在册）。

### 3.10 标定/外参域（v3 新增类）

**两域各是什么**：SITL 相机-IMU 外参=SDF 刚体精确推导（estimate_extrinsic=0 冻结，值即真值）；实机=实测标定（同 0 冻结），带出厂内参残差与标定误差——单一个外参/坐标系误差是**系统性、能盖过 ATE 量级**的存在。

**anchor 双口径（实拉样本）**：odom↔世界坐标对齐的官方口径（DUAL-ANCHOR recompute，viz 平台判读用）在跑过的轮里稳定 ≈ **(1.012, 0.980, 0.105)**；但 round.log 里的**运行时逐轮 anchor 明显飘**：

```
S1  run_M3RE12O_2_164230   (1.043, 0.988, 0.134)
S2  run_M3RNE8O_1_164750   (1.069, 1.048, 0.097)
S3  run_1aO5_NE12O_032934  (1.070, 1.070, 0.076)
S4  run_1aO4_E8O_032707    (1.121, 0.951, -0.019)
NE4 run_C3NE4_020836       (1.121, 0.810, 0.032)   ← 官方 recompute = (1.012, 0.980, 0.105)
E2  run_C3E2_013723        (-2.992, -0.010, 0.117) ← 该轮已定案异常
```

官方值稳定、运行时值逐轮飘（正常轮偏差 ~3-11cm，异常轮米级）——**帧对齐本身就是一个需要显式管理的量，不是常数**。两套口径差=判读时用哪个 anchor 的选择，直接影响真值对照类指标（ATE/到位）的数值。

**对结果的影响**：①SITL 外参=真值 vs 实机外参=带误差估计——实机对竖直机动敏感（E12/E13 在册）；②任何跨轮真值对照必须声明 anchor 口径（本项目=官方 recompute 口径，运行时值仅作轮级健康探针）；③实机首飞判读若用 VINS 自报做相对评价，此域风险自动规避（无真值对照）。

## 6. 可信度边界（最终答案；v3=差分台原则+证伪条件版）

> **差分台原则（v3 写死）**：SITL 是**差分台，不是判决机**。世界纹理是我们自己拧的旋钮（plain 0.16-0.28 / obstacles 0.05-0.08 / corridor p50 0.810），任何 SITL **绝对**成功率都无跨世界意义；**只有同世界+同配置下的 A/B 对比可外推**。本文一切"绿率/成功率"表述均绑定"世界+配置"前提；结论 v2 起对外陈述同口径。

- **可外推到实机（各条含证伪条件）**：
  1. **算法逻辑正确性（绕障/到位/控制闭环）**——前提：深度/障碍链同构（待核②，**2026-10-17 已闭合**：SITL 规划器输入源=gazebo 深度图话题链，与实机 rs 深度流同一 grid_map 消费代码，§3.1 表）。**证伪条件**：若实机深度流在贴障区间出现 sim 未建模的空洞/噪声使 grid_map 建图失效（min-Z 边界/主动 IR 白静区空洞，受限空间节），则"绕障逻辑正确"降级为"绕障逻辑在理想深度下正确"，实机表现另测。
  2. **任务流程与故障处置逻辑**（状态机/降级链结构）。**证伪条件**：实机 failsafe 参数集（待核④）与 SITL 配置分叉到行为级差异时，处置逻辑结论按分叉面收回。
  3. **判读方法论框架**（分层/门组/相对量正源）。**证伪条件**：无（方法本身）；但具体数字禁跨域互比（§3.8）。
- **不能自动外推（各条含理由）**：
  1. **任何具体数值**（成功率/精度/绿率——绑定平台+纹理难度+配置集）；**证伪式声明**：换世界即换数字（差分台原则），不存在"仿真绿率 X%"的跨世界陈述。
  2. **控制参数表现**（H4 修复需实机动力窗复核）——若实机动力辨识（待核③）显示 iris 默认参数与真机差到增益域，SITL 调参结论整体重验。
  3. **鲁棒性余量**（振动/气动/供电/USB 等实机独有应力）。
  4. **人机接管面**（仿真结构性无 RC，no_RC 定案）。
  5. **贴障区间的联合表现**（v3 新增，§3.9 张力）：绕障成功条件与 VINS 失败条件同区间——SITL tag 治理后的贴障成绩是"理想供给上限"，非实机预期值。
- **实飞第一检验面**：架构级硬差异（合成感知/三钟+串口/理想动力学/机载平台）+新增面（RC/failsafe/HAFIX 空中效果）同时第一次真实受考——已知风险都有预案（振动→滤波面、链路→投递纪律、平台→敌对态前科、起飞族→H4 修复+预授权链+手动接管兜底、供电→监控三线+非正常停机前科意识）。
