## 章 1 项目概览与目标

**导语**：一台 250mm 轴距四旋翼，纯视觉（双目+IMU）自主导航，不许用 GPS。项目用 16 天走完了"复现上游→SITL 仿真验证→实机地面链→实飞前夜"全程，本报告是这段路踩过的坑与沉淀的方法的总账。

### 1.1 复现目标与本体

复现对象=浙大 FAST-Lab 开源的 **Fast-Drone-250** 全栈自主飞行方案。四个核心组件各答一个问题：

| 组件 | 回答的问题 | 本项目角色 |
|---|---|---|
| VINS-Fusion（双目+IMU 视觉惯性里程计） | 我在哪 | 唯一定位源（纯视觉红线） |
| EGO-Planner（ESDF-free 局部规划器） | 沿哪条线飞 | SITL 验证 5/5 后转实机 |
| px4ctrl（机载位置控制器） | 这一瞬间怎么飞 | 安全链 HAFIX 的宿主 |
| mavros+PX4 v1.17.0 | 把意图变成电机转速 | 姿态环+失效安全底线 |

架构关键点（实机与 SITL 同构，R6 红线）：planner/px4ctrl 的里程计**直连 VINS** `/vins_estimator/imu_propagate`（IMU 率高频外推流），不绕 PX4 EKF2 位置融合；EKF2 仅通过 `vins_to_mavros` 桥吃 ~10Hz 视觉位姿做自身状态机的第二意见（EV_CTRL=0 全历史，EV 融合从未启用——见术语表）。

### 1.2 纯视觉无 GPS 红线（用户 2026-09-28 裁定）

**是什么**：用户原话"我们是纯视觉导航不许依赖 gps"。落库为 README §0 架构红线 R1-R6。
**为什么**：实机是 D435（无 i，无相机 IMU）+VINS，SITL 里 Gazebo 注入的 GPS 只是流程代位——在 GPS 代位链路上精调的参数（磁配方/GPS course 流程）对实机零迁移价值。T3 曾差点把"先飞 2m 建立 GPS course"写成修复配方，被用户当场纠正。
**执行面**：①任何修复方案先过"无 GPS 可行"检查；②SITL 定位层验证必须走 iris_stereo_vins+sim_vins.launch+run_ctrl_sitl_vins.launch 三件套（全在库）；③GPS 代位仅做流程/规划/控制层验证且必须标注；④ulog 融合分析用 estimator_aid_src_external_vision 而非 gnss 源。
**再遇到怎么复用**：架构红线要"成文+入库+每份任务书头部引用"三件落地，口头共识活不过三个会话。

### 1.3 两阶段路线与交付物定义

- **阶段一 SITL**（09-22→10-07）：PX4 SITL+Gazebo+双目 VINS 同构链，判读自动化，目标是"仿真域把病看透、把修复验实"。

### 1.4 tag sitl-v0.4 的语义

**是什么**：2026-10-07 04:10:54 打出并推送的 annotated tag（挂 commit dd8dfda）。
**内容**：X4 五位形 5/5 全物理绿、零门拦截计入、双链核验（内嵌判读全绿 ∧ T3 影子复核 7/7 逐位一致）、物理绿≥3 的验收口径全部满足。
**语义**：它不是"仿真全过了"，而是**"在预注册的选格口径下，无门基线的物理绿率验收通过"**——tag message 里自带成色注记（no-gate baseline/phys=5+intercept=0/双链），谁检出这个 tag 谁能看到它的边界。这是"验收断言与版本号绑定"的实践：结论的适用范围跟着 tag 走，不靠人脑记。
**教训（可复用）**：tag 要写"怎么验的"而不是"通过了"。后续任何人复跑，判读脚本+口径+config md5 都能从 tag 注记溯源。

## 章 3 SITL 战役全史（核心章）

**导语**：SITL 域 16 天回答了一个问题——"这套栈在什么条件下能物理绿，绿不起来的病根在哪"。答案分三层：选格（gyr 剂量）决定绿率上限；时戳配对决定跳变族生死；慢淋 transit 是无回环 VIO 的架构地板。本章九节，每节都是"症状→判据→工具→坑→处方"的完整教学件。

### 3.0 前史五案（10-01~10-07 早期战役——tag 之前的主战场）

**导语**：X4/tag 之前，route 线上打了六夜恶仗。这五案是后来一切方法论（分账/预注册/统计化验收）的孵化器。

#### 3.0① route 假盆地战役

**是什么**：route（航点导航）五位形早期全灭的根因链——"猛动态起飞→VINS 病→规划链背锅"的真相是**估计器 init 后假盆地**。
**症状与数字**：起飞狂飙段双目匹配几何性失败→**负深度伪注入 13-28 帧/帧**→init 后 4.3-78.7s 脆弱窗内 Bas 爬坡>2.5，假盆地成熟（空中再 init 落假盆地=新前沿：033941 十四连 reboot 后 491m 假盆地、035800 成熟 69-91m）。
**怎么排除的（六项钉死）**：传感器噪声（用户 10-03 深夜亲自做 **0 噪声实验**：完美 IMU 照样爆）/IMU 喂毒（glitch 取证）/init 落错坑（18 段首诊断全干净）/栈差（回放逐位中性）/规划器（T3 无罪）/求解饥饿（R3x 证伪：21 轮 slv_ms p95≤27ms 全离界）。复验复原对账=双目 rig 与从未动过的镜像**逐字节一致 974a7533**。
**修复两案竞速（已批后写码）**：案 A 分阶段门（init 填窗期保留伪注入+稳态期拒收；复裁 R1=3/4 **案 A 胜**——A2 到位 0.633 破 0.75 门）vs 案 B W4 前置线 0.5 硬线可配化。**冲突约束实证**（depth-gate 臂负结果带机制证伪）：毒载体清除成功（ir_st→0）但特征弱化→solveGyroscopeBias 降质→W4 门 |Bgs|<0.5 活锁 1.1s 循环→盲飞——**拒垃圾深度保护 Bgs 解 vs 拒帧饥饿活锁，是同一枚硬币的两面**。
**三题收缩定案（10-03）**：A 假盆地=唯一堵点（两案已批）；B 轮间散布=**时序彩票转知识**（种子=异步时序+物理微动经闭环放大，t=31s 首分叉链路被直接观测；单轮=彩票、验收必须统计化）；C 到位地板=0.79-1.10m 全在 0.75 门上（零噪声健康轮照样只到 1.03-1.10m=**结构性慢漂地板非爆**——X4 撞门预警、U5 升格、"到位 FAIL 两味分层"判读口径由此立）。
**再遇到怎么复用**：多因混浆的大问题先做"收缩"（切成互不纠缠的子题再逐题定案）；"零照样爆"的对照实验比一百次加噪分析值钱；修复案竞速要预注册复裁判据（3/4 过线=胜）。

#### 3.0② CauchyLoss(0) 毒配置风暴案

**是什么**：一个 sed 手滑把 cauchy 4.0→0.0，引发的 NaN 代数炸弹+110 次 reboot 风暴——"毒配置轮拉低全库绿率"的账本主案。
**五环链（T2 v9.8 C.1 定案+T1 v11.13 独立定案互证）**：臂 sed cauchy 4.0→0.0 × vision_loss=1 → **CauchyLoss(0)=NaN 代数炸弹**（loss 核宽为 0）→①INITIAL 111/111 -nan 仍被后置门放行（门只查状态有限性，不查中间量）→②marg prior 污染（1051 FAILURE 帧与 ceres dump 一一对应）→③**cost gate 假触发代数**：median 退化到 -1 时判据 `-1 > 10×(-1)` 恒真（NaN 帧反而清零 streak）→110 次 reboot 风暴→④staged 键结构性哑火（配置分阶加载没接住）。
**怎么验证的**：VRFY1 风暴轮回放逐位复现；"-nan×1066"=T2slv 955+T2OPT 111 分账闭合；**RAREP1 复刻实验**（cauchy=4.0 重建）PASS=因果单向确认；T1 侧 15dc20d 独立定案 5/5 跨 boot 绑定（同一 config md5 的轮全部中招）。
**修复（NaN 四防线，10-06 落码）**：D2 参数域断言（毒配置拒启，实证）/D3 init 后置门加 cost 检查/D4 cost-median 守卫/D5 prior 防线；gtest 128+3 全绿；栈换代 vins_node 721cad40/libvins_lib 5bacc2e9。
**再遇到怎么复用**：鲁棒核参数=代码级红线（0 宽核=除零炸弹）——参数域断言要在**加载时**拒，不能等运行时症状；判读"门未触发"时先查门的代数退化面（median 恒真/恒假都是病）；全库绿率统计前先剔毒配置域（config md5 分账）。

#### 3.0③ E 系列 EV 战线

**是什么**：关于"PX4 EKF2 要不要吃 VINS 视觉里程计"的整条考证线——结论是**从未启用，且上游也不喂**。
**架构发现（E1）**：**EKF2_EV_CTRL=0 全时线**（09-22→09-29 全部 90+ ulg 零例外；cs_ev_pos/vel/hgt/yaw 整轮 n_true=0，而 vehicle_visual_odometry 全程健康到达 ~9.6Hz）——**EV 数据到达但从未被融合**。根因=iris_stereo_vins 挂标准 iris airframe（不设 EV_CTRL；对照 iris_vision airframe:12 set-default 15），参数从未被显式管理。

### 3.3 输入门战役全案

**是什么**：试图在 VINS 前端加"输入质量门"（视差/深度/配对率三键，拒掉坏帧）来治跳变族的整条路线，最终整体证伪。
**演进四段（每段都是独立教学件）**：

1. **视差门判负**：毒在 motion2 远特征（p99 距离 696-865m 的虚假远点），门剔的是近特征——**错轴三重收杀**（剔好留坏+拒帧饥饿+参数无自由度）。视差是"运动量"代理，不是"特征质量"代理。
2. **cost 门首证**：滑动短窗 cost 中值（W=20 短窗中值×R=10 相对阈）在离线回放上能定位跳变——但六面检验全负（3.7 节门科学包）：绿轮 cost 天然 lift 10-50×（GROUND→POST 生理性 8-20×+跨世界基线差 ~10×），巨跳轮 E12P 36m 跳 cost lift 仅 1.63 全程静默；现行 cost 门（R10N5）X5 全批 59 轮**零触发**实证。
3. **门参数化整体证伪（M3' 判读）**：N8P base 3/3 绿→带 v2.0 门 0/3 全 FAIL——**饥饿复现铁证**。机理链：1a 分带标定证明两域（plain/obstacles）输入分布重合（stereo_r p50 0.780/0.770）→M3 v1.1 所谓"场景依赖"实为**门-饥饿反馈产物**（v1.1 阈 0.10≈健康带下界 L=0.095，参数无自由度）→**3-4 个拒帧即触发跳变雪崩**（格子×时序敏感）。REGEN v2.0 FROZEN（gate yaml 26c544dc，stereo_r L=0.095/U=0.895）只是把"门在哪里必然失血"钉死在文书里。
4. **observe 模式与 A1 不收敛**：门改 observe（只报警不拒帧，IQG 逐帧 METRIC）后结构性无饥饿链，但 **A1 扩批 12/12=N8P 2/6+E8P 0/3（毒域）+S8O 0/3（彩票带）=混合带证据不足**；N8P 彩票格 p̂≈0.5 时 9 轮样本的双侧分辨极限 ±30pp——**结构性不收敛**，扩批只买噪声。

**怎么验证的**：预注册分支兑现制——M3' 判读前把"3/3→0/3=证伪"写进判据，结果如实落；A1 按预注册"证据不足"分支逐字入册，禁以机理替代判定。
**机理（为什么门必败）**：门是**循环的一部分而不是旁观者**——拒帧改变估计器看到的世界，饥饿改变特征质量，特征质量又回到门的输入。在闭环系统里调"开环阈值"，等于在优化器肚子里调参数。修复面最终钉死为二选一：候选 A 循环打破（报警不拒帧/fail-open）∨候选 B 弃门转输入编辑（1c 编辑器路线）。
**再遇到怎么复用**：给估计器加输入门前，先跑"分布对照"（两域输入分布重合=门无判别轴）+"拒帧-状态耦合"思想实验（拒 3 帧会怎样）。**在闭环里，任何"看似只读"的过滤器都是写操作**。

### 3.4 50pp 波动案与统计化验收

**是什么**：同一夜、同一栈、同口径的三批 B 臂基线，绿率 50%/75%/25% 摆动——表观"夜态漂移"。
**数字**：WU2/②a/②b 三批 B 臂 50/75/25%（d198718f 全 32 轮一致；±15pp 判据阈值<波动幅度 1/3）。
**怎么发现的**：T3 v11.1 判读 ②a 臂批时发现 A 12.5% vs B 75.0%，同夜 ②b 批 B 臂又变 25%——三批判读以配对差为准的纪律救了这案（单批判读会得出"B 臂恶化"的假结论）。
**怎么验证的（二项分解定案）**：批绿率=2+Bin(4,0.5) 分布——75/50/25 恰为均值±1σ，**纯二项抽样噪声内的夜态漂移非必需**；同窗交错 BX/WU2 差 25pp=至少 25pp 非时段效应；Fisher p=0.07 暗示性未确立。
**推论（判读方法论级）**：**8 轮批的组间分辨极限=±25pp**。任何小于 25pp 的组间差异在 8 轮批上不可判；要分辨 10pp 级差异需要 ≥50 轮批或配对设计。
**再遇到怎么复用**：臂对实验必须同批配对（A/B 同格同夜），跨批判读只看配对差；看到"50→75→25"第一反应查二项噪声而不是查环境；预注册里写明批宽与最小可分辨效应量。

### 3.5 预热战役全案

**是什么**：试图在起飞前注入 8s 旋转激励让 VINS bias 收敛（静态不可观→激励可观）的整条路线，最终证伪。
**动机（机理）**：VINS 的 IMU bias（Bas/Bgs）在纯静态下不可观（重力方向歧义），bias 收敛慢→带病起飞。社区有"旋转激励法"先例（VINS-Fusion #41 等同病谱印证）。
**六段演进**：
1. **设计**：8s 激励（warmup goal 流）→三臂对照（预热/无预热）。
2. **首夜判读 NOT-EFFECTIVE 但根因不在激励**：A 臂 8 轮全悬停未导航——**harness goal 切换 bug**（warmup 尾 10Hz goal 流把 ego FSM 拖入 EXEC/REPLAN 自环永不回 WAIT_TARGET→planNextWaypoint 非 WAIT 态走 REPLAN 侧失效）。此时"激励本身未被证伪"（A 臂帧稳定 6/8 反优 jump 0.037-0.222）。
3. **修复三件（W1/W2/W4）**：W1 goal-silent 稳定门（20s 等 WAIT_TARGET 回转——批内实证 7/7 等不到=W2 是承载路径）+W2 重启兜底（25s 超时重启 planner，starve#1 二重启兜住=冗余生效）+W4 采纳验证门。案③提频重发被既有数据证伪排除（mission goal 16 发全灭=失效与频率无关与 FSM 态有关）。修复后干测铁证=planner INIT→WAIT_TARGET→Triggered→GEN_NEW_TRAJ→EXEC_TRAJ+机体位移 x 0.29→8.28 飞向 goal。纯加性 237 字节+WARMUP=0 路径逐字节不变。
4. **复验 8/8 对 NOT-EFFECTIVE 干净定案**：A 12.5% vs B 50%，**-37.5pp**，方向 3/8——goal 面修复后，激励本身被证伪。
5. **"A 臂帧稳定反优"勘误=悬停混杂**：不导航就没有跳变机会；修复后 A 臂 transit jump **劣于** B 4/7 对=**预热自伤**（激励把 bias 推入大瞬态带，病着起飞）。
6. **与实机的关系**：实机静态病理（章 5.5）的处方是**重启规程**（间隔>5min 重启 VINS）而非预热——预热在 SITL 证伪后，实机侧直接采用重启制，两域结论互洽。
**怎么验证的**：每段都有预注册判据+配对批+机制面（帧稳定/jump 分布）三面。
**再遇到怎么复用**：激励类干预必须先证明"激励到达了"（goal 采纳验证）再评价"激励有没有用"——W4 采纳验证门是这类实验的命门；"反优"结论要先剔除机会混杂（没导航就没有失败机会）。

**复盘（如果重来）**：warmup harness 首夜就该带 goal 采纳断言（发布≠采纳）。8 轮 A 臂全悬停的数据如果没被"帧稳定反优"的表面现象迷惑，能早一夜定位 harness bug——教训是**干预实验的第一判据永远是"干预是否到达"**。

### 3.6 bias 约束战役

**是什么**：约束②——在 VINS 优化器里给 bias 加约束（盒界/相对锁）治漂移的路线，四案整体证伪。
**数字与判据**：
- **②a box ±0.5m/s²/±0.05rad/s**：机制面全生效（indom 100% 8/8+dbadt 改善 6/8+慢淋被治 7/8）**但绿率 -62.5pp**（A 12.5% vs B 75.0%）——钳 bias 反伤：被压住的 bias 误差**转移进位姿**（z 1.039m 降落失败案例=误差进位姿的实物证据）。
- **②b tlock 相对锁（transit 期锁 bias）**：+0.0pp 无效。第一层判读发现 banner=0×8（锁未 ENGAGE，A 臂=第二 B 臂）——**banner=0 是批脚本 L56 grep 错模式（②a copy-paste）的判读侧伪影**，vins 侧 8/8 实际 ARMED+ENGAGE。第二层真机理=**窗错位**：冻结谓词 V>0.3 捕获的是**起飞爬升段**（VINS 地面完成初始化→NON_LINEAR 先于起飞）+单窗语义→真 transit（t≈47-53s）全程未锁。并存机理：锁窗与 dbadt 度量窗同窗（7/8 折算逐位吻合）。
- **前置案**：FEED（bias 喂入）10-08 判负——mavros 标准话题面结构性无 EKF2 bias（sensor_msgs/Imu 无槽位+ESTIMATOR_STATUS 无字段+data_raw−data 差分噪声主导）=NO_VALID_CARRIER；预热 10-09 判负（3.5 节）。
**四案夹逼定论**：**约束漂移可治（两案机制面 dbadt 全治）但绿率对 bias 约束零响应**。box 生效却 -62.5pp（误差转移）、tlock 生效却 +0.0pp（锁错了窗）——漂移不是绿率的瓶颈因子。
**SITL bias 漂移的定性**：功能性适应非病理（SITL 的 bias 漂移吸收是估计器正常行为）；域边界声明——实机真温漂场景的工程价值未被此证伪否定（复审条件=实机真温漂场景，unit4 注记档案 bb161a2e）。
**落码资产**：t2_bias_box.h（盒界+窗谓词共享头）+estimator.cpp L1429 盒界/L1511 transit 锁+键 t2_bias_box/t2_bias_tlock/t2_bias_tlock_w+banner 三件+gtest 7/7，**全默认 off=legacy 逐位同**——证伪的路线也要留可复现的开关资产。
**再遇到怎么复用**：约束类修复先问"误差去哪了"——不可观/弱可观量的约束不会消灭误差只会搬家（bias→位姿）；判读 banner 类自证日志前，先确认 banner 是 vins 打的还是批脚本 grep 来的（**grep copy-paste 是 banner 伪影第一来源**）。

### 3.7 三臂 δ 实验（输入面定案的核心实验）

**是什么**：把"病在输入面"从假设变成定案的受控实验——三臂分别扰动时间戳配对（A）/发布节奏（B）/消息内容（C）。
**动机（怎么走到这一步）**：1e 回放裁决=E8P 2/2 回放全部 11 个巨跳同刻同幅复现（多处 0.01s 逐位）+HVNET1 慢漂确定性复现（终态差 1-2.4%）——**同输入→同输出，病在输入面**（渲染域）；估计器内部仅"定弹道"（r1↔r2 分支 10/28 bin 差=路径层非确定性）。
**设计与结果**：
- **臂 A（时戳配对）=唯一敏感因子**：δ（左右目时间戳差）≤2ms 跳变瀑布带内/δ≥5ms 12 轮逐位收敛稳定态——**陡峭相变 2ms<δc<5ms**。

- **臂 B（节奏四操作 8 轮）/臂 C（内容替换 4 轮）=全瀑布 NO-EFFECT**（maxjump 69-87+nj 942-2532 同基线带）；臂 C 消除未触发→场景改造条款关闭。

**副产物（实机注记）**：实机 td 控制域 |td|<2ms 预警；D435 硬同步 δ=0 结构性配对域无共振路径（实机免疫此病的架构理由）。

### 3.8 时戳病理归因链

### 3.9 transit 慢淋族

**是什么**：转场段（悬停→航点→悬停）里程计缓慢漂移，1.6m 级到位地板，占失分 24.0pp 的第二大族。
**数字**：BL5=transit 98% 地板实证（j0_decomp v1.0，1f5a806d）；BL7/5=70 倍分离=平滑盲区度量衡（慢淋在"平滑度"指标下隐身）。
**机理（无回环 VIO 先验锁定）**：转场中大视差特征三角化出伪深度（ INIT_DEPTH 兜底 5.0m）→伪深特征满权重进入优化→双稳态翻转（错误解把正确解挤出去）→边缘化把错误状态写成先验→**"错误被信仰化"**（先验锁定后无法自愈，输出连续一致但错误）。
**回环不接入裁定（用户 10-04）**：回环 pose_graph 默认不接（案 A），保留开关。论证：①上游 Fast-Drone-250 实机同构不接回环；②回环治漂移但引入重定位跳变+计算负担，与"高频低延迟直连"架构取舍冲突；③SITL 域回环收益未验证（悬停无回环低预期登记在案）。
**修复面定位**：架构级 transit 地板（回环不接入维持）→绿率修复收敛为"选格 70.5%+止损件+架构地板如实标注"三层。
**再遇到怎么复用**：无回环 VIO 的慢漂是**架构地板不是 bug**——别试图在参数层治它；判读时用到位分解（planner 无罪+执行段伪影分离）而不是终态单指标；"输出连续一致"不等于"输出对"（先验锁定的病最会伪装健康）。

### 4.1 敌对态机器层翻案

**错误结论**：T2 早期（10-01~10-04，旧 NUC 域）出现"敌对态"轮——输入四面全净（图像/IMU/config/负载）却发生 HF 坍缩、流停摆、内部翻转（8 例进程内铁证：输入四面全净+进程内非确定性翻转）——一度定性为"VINS 算法在特定输入下有病"（ζ 机制假说族：双稳态翻转×LK 饥饿×伪深满权重）。
**翻案证据链（三步夹逼）**：①图像对审 v1.2=B+ 两型均不可分（敌对轮与健康轮的输入图像统计无差异）；②R3x 时序排除（连续稳定带 sc≤0.17，非时序累积）；③8 例进程内铁证（同一输入、进程内部翻转）→嫌疑收窄到"机器层×进程内"；④**决定性实验=3090 全项目迁移对照**（10-04/05）：同一栈（md5 一致）、同一批式、不同机器——**敌对率 83%→17%，形态学剧变（极端失控 8→0、风暴型 1→10），而 92% 大漂移率恒定**。
**定案**：旧 NUC 机器层（硬件/内核/资源面）是敌对态触发器——**机器层改变故障形态但不改变大漂移发生率**；形态学证据（失控/风暴分型）不可跨机器比较，发生率口径（大漂移%）才可迁移。
**教训（可复用）**：①"输入全净+进程内翻转"的下一跳不是更深挖算法，是**换机器跑对照**——双机对照是软件/硬件分诊台，一次迁移顶一百次日志分析；②跨机器对比必须**预先固定可比口径**（栈 md5+批式+判读器版本），否则形态剧变会淹没真信号；③旧机器的"病栈"不要急着修——可能是好栈跑在坏机器上。

**复盘（如果重来）**：ζ 机制四证链（双稳态×LK 饥饿×伪深）在旧机上"证据齐全"地自洽——如果 10-01 就做一次 3090 预迁移冒烟，能省三夜的机制深挖。**自洽的机理叙事是最危险的：它解释一切也阻止一切**。对照实验要在机理故事讲圆之前做。

### 4.2 anchor 算术 bug 翻案

**错误结论**：X2 线判读宣称"22/22 轮动态窗 z 污染"=VINS 在转场/悬停切换时有物理级 z 瞬态（当时据此立项修 VINS 的动态窗处理）。
**翻案证据链**：判读器 v1.4 自审计发现历史锚计算=**sum(前 50 帧)/len(全窗)**——分母用了全窗长度而非求和窗长度，锚点系统性偏移；修正后 X2g3 案 0.849→0.035 翻绿（门内）；99 轮全量重判 15 轮翻转（判负→判绿）。
**怎么发现的**：一位执行者在重跑锚点哨兵时发现"锚点值与直觉量级不符"，回头审计判读器源码——**工具自身的算术被当成了被测对象的物理**。
**教训（可复用）**：①判读器是测量仪器，仪器要**定期对已知量自校**（锚点哨兵 v1.0：冻结锚点+三表签名+selftest 7/7，正是此案的直接产物）；②"N/N 全污染"这种完美整齐的结论本身就是危险信号——物理世界很少整整齐齐，算术世界经常；③翻案后必须全量重判（99 轮 15 翻转），不能只翻发现的那一例。

**导语**：实机阶段五天（10-07~10-11）没飞一步，但把"上电→采数→判读→安全→运维"整条地面链跑成了可复现工艺。本章八节，前四节是四个侦探案（IMU 频率/USB 断链/E8P 毒域/静态病理），后四节是质量与运维（画像/内存/方法论）。

### 5.1 实机栈与硬件基线

**是什么**：实机地面链的五件套与硬件事实表——后续一切实机工作的地基。
**硬件基线**：FC=Auterion PX4 FMU v6C，固件 v1.17.0（10-09 重校实证：固件版本+FMU 型号双确认）；相机=RealSense **D435（非 d435i）**——`Imu Type: IMU_Unknown`=**无相机 IMU**（上游 Q&A"d435 imu 噪声大"的工程否决+本机硬件双证）→**IMU 唯一源=mavros**（/mavros/imu/data_raw，与 SITL 的 PX4→mavros 链路恰好同构=R6）；D435 factory 内参 fx=387.508 系（camera_info 直读=上游方法，与标定差 0.81% 阈内）；双目=640×480 Y8 @30Hz（infra1 29.98/infra2 29.96Hz，硬件同步 δ=0）。
**五件栈（命令正源）**：roscore → mavros → vins_to_mavros → ego_planner+traj_server → px4ctrl（+watch2/kill_watch 两个看门狗伴跑）。配套：config v0 三件（上游基线+本机内参+cauchy4 键 t2_cauchy_delta=4.0+回环不接）；OS 调优 rc.local 三件（governor=performance+USB autosuspend off+swappiness=10）；1g 手册 v0 含上游五 case（5ch 退出/6ch 悬停/7ch 急停）。
**频率结构（用户问"10Hz 是哪个"的标准答案）**：相机 30Hz（视觉节拍）+IMU 50Hz（FC 默认，提频后 ~202-203Hz）+imu_propagate 50Hz（IMU 传播流，非视觉频率——常见误读）+traj_server ~100Hz+重规划事件触发；**项目里出现过的 10Hz=预热激励 goal 流（harness 注入，非飞行链路）**。
**再遇到怎么复用**：实机栈清单要"命令级+参数级+频率级"三层落盘（五件栈命令正源/config md5/频率表），排障时第一件事=对表找哪件缺了/慢了。

### 5.2 IMU 频率案

**是什么**：实机 IMU 从 FC 默认 50Hz 提到 ~203Hz 的完整论证与实测。
**三层根因（SITL 域先挖穿，实机复用）**：①50Hz=PX4 v1.17 mavlink_main.cpp MAVLINK_MODE_ONBOARD 分支硬编码 `configure_stream_local("HIGHRES_IMU", 50.0f)`；②125Hz 天花板=lockstep 4ms 网格量化（5000µs 请求每次到期落在两网格点之间→量化到 8ms 周期）；③修复=**MAVLink 511 命令 `rosrun mavros mavcmd long 511 105 4000 0 0 0 0 0`**（4000µs 对齐 4ms 网格）→SITL 实测 223.7Hz；实机同命令实测 **~202-203Hz（500Hz 请求=链路上限实测）**，与上游实机 250Hz 对齐论证（BMI055 陀螺 ODR 2000Hz 驱动写死 2000÷8 分频=严格 250.0，实机无 4ms 网格）。
**时间戳抖动实测（"频率高但抖怎么办"的完整答案）**：dt 波动 2.3-7.5ms **无害**——VINS 逐样本时间戳算 dt，不假设均匀节拍；**真正进 dt 的误差=相邻消息延迟差**（p50=0.039ms/p95=1.88ms，串口延迟的公共部分被差分消掉=timesync 映射的串口延迟剥离机理）。
**假说否证**："203Hz 压垮全家桶"——静置实验否（全家桶仅 1.7/8 核占用）；"848 宽度 USB 超限=线材故障"——澄清=D435 多路流等时传输预留带宽，848 组合超 USB3 控制器预算（Intel 官方已知现象），640 组合约减半进预算=稳定档。
**不用 90Hz 低分档三硬约束（算力/IMU 配比/上游同构）**：①13.8ms 求解+跟踪 20-30ms/帧 vs 11ms 帧间隔=必然饥饿；②50Hz IMU/90Hz 视觉<1 条/帧=预积分退化（现 50/30=1.67 条/帧已偏紧，上游标准 200Hz）；③上游实机=640@30。
**再遇到怎么复用**：提频一律用 4000µs（≤4000 均可）；测频率用 bag header-stamp 直方图而非 rostopic hz（后者会漏结构信息）；链路建立前发的 mavcmd 会静默丢且 exit 恒 0——**发完必须验证到达**。

**症状**：实机静置（不动）VINS 出现三症状链假设：|Bas| 漂大→cost 爆→崩（10-08 首次活体：|Bas|=1.03 病理+cost 3.3e8 爆+Eigen 断言崩）。

**再遇到怎么复用**：静态不可观是 VIO 的物理本性——静置越久 bias 越漂；**处置不是治是躲**（重启规程+起飞前自检），别在参数层治物理。

### 5.6 实机质量画像（九袋判读）

**是什么**：r1 旧批三袋（USB 病理）+r2 重录四袋+scen0 静置袋+缓动袋=九袋 odom 流 j0d 判读，实机域的第一份质量底账。
**数字**：**scen0 静置净轮 coh=0.0007（噪声型漂移）vs sim 慢淋 coh≈1.0（结构型漂移）=三数量级谱系分离**——实机静置是白噪声，SITL 慢淋是相关游走，完全两类病；缓动 0.214m/min 混合型=**实机 transit 首观测**；走动 30m 往返差 0.058m；平移多趟散布 0.07m。
**实机绿率预期论证**：SITL 两大病理——跳变族（时戳域）实机**免疫**（D435 硬同步 δ=0+3.8 节归因链）；慢淋 transit 实机**轻三数量级**（coh 分离）→实机绿率预期显著高于 SITL 的 ~30%，主要残余风险=静态病理（5.5）与内存泄漏（5.7）两运维项。
**再遇到怎么复用**：跨域质量对比用**漂移的自相关结构**（coh）而不是漂移幅度——幅度混类别，结构分病种；"仿真 pessimistic、实机 optimistic"的论证必须落到具体病理的域归属，不能笼统说"实机更真实"。

### 5.7 内存泄漏四部曲

**是什么**：VINS 进程 RSS 线性上涨的完整取证链——从现象到行号级归属，四步一部曲。
**第一步（发现）**：RSS 涨势（0.6→1.45GB/h 非平稳）；odom 15→5.7Hz 劣化@9.4h；重启即复。
**第二步（统一模型）**：**2.18GB/h×健康帧占比**——SEG2 十一窗精确线性；"0.6-1.45 非平稳"之谜=平台相与健康相混合（病理发作期=泄漏暂停的中断 7h 期间 8.79GB 零增长=第二数据点；**同源首测=非同源+反耦合**——"一修治两病"不成立）；指纹=滚动 arena 40KB/帧；实机第三/第四数据点=1.44/2.09GB/h 同带（模型跨域成立）。
**第三步（五假设排除+L0 段级）**：输入队列蠕动（滞后 0.999947）/边缘化因子（树已带修复）/path 累积（1-2%）/socket 背压（Send-Q=0）/特征数标度（比 1.17≠2.0）全排除；smaps 双快照 L0 定案=**新增段型 arena 泛滥**（共同段增量仅 2MB/23min 窗新增 15 段 918MB）非主 arena 膨胀。
**第四步（L2 符号级归属）**：heaptrack 三折（①rosrun 形式 LD_PRELOAD 被 ROS 工具链剥离=4K 空文件；②直包二进制符号通但 **VINS init 后一律停摆**——baretest 对照定案=heaptrack 插桩本身所致，第三方 heap profiler 在 VINS 上不可用；③**自研 t1_mtrace.so v4**：`__libc_*` 直连+fopen 重入守卫+≥8KB 分配 4 帧回溯+free 配对+60s still-live 按 caller 汇总；四坑迭代=dlsym 启动段错误/__thread TLS 段错误/fopen 递归爆栈/pgrep 匹配包装进程）→**判决（469e75f2）**：回放域泄漏率 0.95GB/h（0.85-1.11 带，7 实例 1620s 合并）+**行号级三家族**（双证据面交叉=gdb 条件断点 `operator new if $rdi∈(9.5k,13.5k)` 20 全帧+探针 13 实例）：链 A=Estimator::processImage **estimator.cpp:666**+slideWindow **:2188**（10512B 高频线性不还，live 573→1406/120s 不封顶）；链 B=ceres::BlockJacobianWriter::CreateJacobian←optimization **:1736**（11488-12192B 每轮求解）；次级=vins_node 图像 buffer 900KB 族+libopencv 156KB 族（无调试符号包，函数级受阻）。

**导语**：上游 Fast-Drone-250 的实机失效处置=遥控接管+重启大法+短任务（无自动防线）。本项目的安全体系=把上游的"人肉兜底"补成"机器兜底+人肉确认"两级。核心是 HAFIX 看门梯，外围是止损/监控/自检/根除四件，口径是受控失败分层。

## 章 7 判读与工程方法论（核心章）

**导语**：这个项目最大的隐性产出不是修好的飞机，是一套"多 agent 夜间作战的判读与治理制度"。四节：判读方法论（怎么让数字可信）、协作工程制度（怎么让四个 agent 不互相踩）、用户治理决策史（人来拍什么板）、证伪清单（哪些路被证明走不通——负结果的资产化）。

### 7.1 判读方法论

**预注册先行**：判据在跑批之前冻结落盘（"判据未预注册不出 PASS/FAIL"红线，10-02 E4 双峰实录后实操确立）；分支预写（"若 X 则证伪"），结果对号入座——M3' 判读（3.3 节）与 δc 翻案（3.7 节）都是预注册分支兑现的范例。**为什么**：事后择优判据=数据 dredging，绿率类结论会无条件漂向好看。
**判据冻结零变动**：门值/口径/分母一旦冻结，改=新实验（需重新预注册）；勘误例外=口径语义澄清（如 judge 列语义勘误：第 4 列=maxjump 非 j0_end——结论同列自洽不变）。
**双工具互证**：关键判读两套独立工具重判逐位一致才出门（HAFIX 终验 20/20、75bag 独立复算 39+36=75）；判读器自身=测量仪器，要**对已知量自校**（锚点哨兵：HVNET1 4.12 锚+列语义探针+selftest——4.2 翻案的直接产物）。
**锚点哨兵**：冻结锚点（已知轮的已知值）+三表签名+三代再生全 PASS——判读管线任何一环改动，先跑哨兵再出门。
**j0d 三列分账**：jump/transit 恒等式把终态漂移分解成两族（3.2 节）——**单指标判读是口径事故的温床**，"巨跳 8 轮"重分解后 5/8 是慢淋。
**统计化验收**：50pp 案（3.4 节）的推论=**8 轮批组间分辨极限 ±25pp**；臂对实验同批配对、跨批只看配对差；批宽与最小可分辨效应量写进预注册。
**干测先行**：写码类单元先干测（不起飞验证逻辑），HAFIX 梯修复=干测 7 六环闭环先行+批后物理链验证。
**判读纪律三则（坑换来的）**：①批尾 judge 重读为唯一正源（record 收尾中 bag 部分流假象 2 次实录）；②judge 输出先对已知在线锚点值校验再消费；③工具对已知 FAIL/PASS 样本自测对账再启用（无限深度工作法第 3 条）。

### 7.2 多 agent 协作工程制度（可复用工作流资产）

**任务书制**：四线（T1 控制/T2 VINS/T3 规划/T4 判读）各持任务书=夜间执行者的唯一契约；撰写守则五条（09-29 用户裁定）：禁工作流编排（批量取证走脚本串行队列）、研究优先反盲试（开案三步=查外部经验→原理推导+可证伪假设表→全因子分解后实验裁决）、防跳步（每单元收口=穷尽清单逐项打钩）、交叉引用只刷自己那份（绝不代改他线文件——10-01 二次裁定）、等待协议 v2。
**等待协议 v2（"醒来不靠人"，10-02 裁定）**：被阻塞默认动作=会话内 sleep 300 循环轮询至唤醒条件，**禁以等待为由结束会话**；轮询即心跳（每 ~2h STATUS 心跳行）；**池自补给纪律=每册 0 锁可做件恒 ≥3**（打空现场生成）；合法收工仅三种（全部单元+池清空/基础设施杀死/用户指令）。
